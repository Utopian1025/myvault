# Electron 程序在国内网络下自动更新：做法说明

本仓库的实现：`updater.js`（程序里检查、下载、安装）、`scripts/publish.js`（发布时切块、写版本信息）、`.github/workflows/build.yml`（打包和发布流程）。

## 核心思路
国内直连 GitHub 不稳定，特别是 Releases 的大文件下载。所以：

1. **版本信息走多条线路同时查。**
2. **安装包切成小块，放进 GitHub 仓库的分支里，用 jsDelivr CDN 下载。** jsDelivr 在国内访问比较稳，但单个文件不能超过 20MB，所以要切块。
3. **jsDelivr 不通时，再换 GitHub Releases 原地址和几个公共加速镜像。**
4. **下载完必须校验 SHA-256**，对不上就不装。这样镜像被篡改或者文件不完整都装不上。

## 一、发布流程（GitHub Actions，`build.yml`）
手动触发，Windows 打包机打出 `.exe` 以后，在一台 ubuntu 机器上做发布：

1. **准备文件**（`scripts/publish.js prepare`）：
   - 安装包改成英文文件名 `Desktopia-Setup-<版本>.exe`。另外复制一份固定名字 `Desktopia-Setup.exe`，这样「下载最新版」的链接永远有效。
   - 算整个安装包的 SHA-256 和大小。
   - 按 **15MB 一块**切开，命名为 `xxx.exe.000`、`.001`……
   - 用 changelog 生成发布说明 `notes.md`，里面带「GitHub / 国内加速 1（gh-proxy.com）/ 国内加速 2（ghfast.top）」三个下载链接。
2. **发到 GitHub Releases**（`gh release create … --latest`）。
3. **每一块单独放进一个分支** `dist-0`、`dist-1`……：
   - 每个分支都是 `git init` 出来的全新仓库，只有一个提交、一个文件，然后 `git push -f` 覆盖上去。这样仓库不会越积越大。
   - 记下每个分支这次提交的 commit 哈希。
4. **写 `version.json` 并推到 main**（`publish.js manifest`）。内容包括：
   ```json
   {
     "version": "0.14.1", "date": "...", "title": "...", "notes": ["..."], "history": ["..."],
     "win": { "name": "...", "asset": "Desktopia-Setup-0.14.1.exe", "size": 82491117,
              "sha256": "...", "parts": [ { "file": "Desktopia-Setup-0.14.1.exe.000", "ref": "<commit 哈希>" } ] }
   }
   ```
   - 分块地址里用的是 **commit 哈希，不是分支名**。jsDelivr 对固定 commit 的地址会永久缓存，也不会拿到旧内容。
   - 推 main 前先 `git pull --rebase`，最多重试 3 次，防止打包期间有别的提交导致推送失败。
5. **刷新 jsDelivr 缓存**：调用 `https://purge.jsdelivr.net/gh/<仓库>@main/version.json`，每隔 20 秒调一次，共 4 次。jsDelivr 有时要过一会儿才发现新提交。

## 二、程序里检查更新（`updater.js`，在主进程里，用 Electron 的 `net.fetch`）
**同时**请求下面 7 个地址拿 `version.json`，每个最多等 9 秒，地址后面加 `?t=时间戳` 避免缓存：
- `cdn.jsdelivr.net` / `fastly.jsdelivr.net` / `gcore.jsdelivr.net`，地址形如 `/gh/<仓库>@main/version.json`
- `raw.githubusercontent.com/<仓库>/main/version.json`
- 上面这个 raw 地址再套三个加速镜像：`gh-proxy.com/`、`ghfast.top/`、`ghproxy.net/`

所有成功返回的结果里，**取版本号最高的那份**。这样某条线路缓存旧了也不影响。镜像不走 CDN 缓存，刚发的新版能马上查到。

## 三、下载安装包
**线路 1：jsDelivr 分块（优先）**
- 每块地址：`https://<节点>/gh/<仓库>@<commit 哈希>/<分块文件名>`
- 节点轮着用：`cdn` / `fastly` / `gcore` / `testingcf.jsdelivr.net`。哪个节点失败过，就把它排到后面；每块最多试 12 次。
- **3 块同时下。**
- **断点续传**：每块先写成 `.tmp`，下完再改名成 `.partN`。下次启动时，已经有的块直接跳过。
- 全部下完后按顺序拼起来，边拼边算 SHA-256。对不上就删掉全部分块，换线路 2。

**线路 2：整个文件**
- 依次试：GitHub 原地址 `github.com/<仓库>/releases/download/v<版本>/<文件名>`，然后加上前缀 `gh-proxy.com/`、`ghfast.top/`、`ghproxy.net/`、`githubproxy.cc/`。
- 每条下完都校验 SHA-256。

**下载细节**
- **不限下载总时长，只看是否卡住**：连续 30 秒一点数据都没收到才算失败。网速慢的人不会被中途掐断。
- 检查实际下载的字节数和 `content-length` 是否一致，防止下了半截。
- 下载目录准备几个候选：`userData/updates`、临时文件夹、下载文件夹、文档文件夹、系统临时目录。先写一个小文件试试能不能写，挑第一个能写的。公司电脑经常被杀毒软件或权限锁住临时文件夹。
- 如果已经下好、并且校验通过，就不再重下。
- 开始下新版前，清掉旧版本留下的安装包和分块。

## 四、安装
- 安装前**先备份存档**到另一个文件夹。
- Windows 上用 NSIS 安装包静默安装：`spawn(安装包, ['/S', '--force-run'], { detached: true })`，装到原来的位置，装完自动打开新版。然后程序马上退出：200ms 后 `app.quit()`，1.5 秒后 `app.exit(0)` 兜底。不退干净的话，安装程序会报「无法写入」。
- **防止反复重装**：安装前记下「装过版本 X」。如果下次启动还是旧版，说明安装被杀毒软件或权限拦住了，6 小时内不再自动重下重装，改为提示用户去发布页手动下载。

## 移植到别的项目要改的地方
- 仓库名 `REPO`；`version.json` 要放在默认分支的根目录。
- 分块大小保持在 20MB 以下（jsDelivr 的限制）。
- 工作流需要 `permissions: contents: write`，要能推分支、发 Release。
- 加速镜像（gh-proxy、ghfast 等）是第三方公共服务，可能会失效，所以至少放 3～4 个。安全靠 SHA-256 校验兜底。
